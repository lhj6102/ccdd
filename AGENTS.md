Read docs/contracts.md and CONTEXT-MAP.md before changing boundaries.
Definition-only @ccdd/core, project tool @ccdd/project and optional @ccdd/default-tools library; Project Validation, Broker and Executors are separate bounded contexts. Each Artifact folder owns a static ccdd.json with its name, Critics, views and mounts; a family ccdd.json declares a static list of instance Artifacts sharing one folder. JSON discovery never imports config modules or executes scripts. Parent folders depend on their nearest Artifact children; mounts and instruction references add equal-level dependencies. Cycles are supported: SCC peers have no internal gate; external dependency GREEN gates apply unless explicitly ignored. Final verification requires matching actual evidence throughout the required scope. An ordinary no-Critic Artifact is UNREVIEWED; basis is explicit.
The shared local cache maps only explicit owner identity to actual completed result, independent of project/path/Critic/profile. No identity function means no reusable caching. SCC/content fingerprints are execution and graph metadata, not cache salts. Do not import old composite keys. No persistent staleState or push invalidation. Script views use fixed command/args and the versioned JSON stdin/ToolResult stdout contract. Installing libraries never registers tools. Artifact Runner resolves instruction references and logical paths into scoped reviewer-specific tools. No group/generated/source/config-factory compatibility remains. Historical input versions are result-only, never reused or resumed.
Reviews use the supplied unchanged workspace without copies or remote transfer. Cache-owned computations are independent of caller receipts; one subscriber cancellation must not stop another. A cache-owned computation is bound to its owner identity: it never watches or walks the workspace, and it re-runs the identity before accepting a result. Workers of other Runs monitor input throughout Human waiting. CCDD owns bounded Provider recovery and cache GC. The optional loopback monitor delegates explicit current-input inspection to Project Validation and Human claim, tool and result actions to the Broker. GET requests never load user config, execute tools, reconcile or mutate stored review state. Store serializable manifests and reconnect scripts from the same input. Keep state and outputs outside reviewed input.
Individual verification executes selected Critics and reports missing final evidence as INCOMPLETE; recursive verification includes the required dependency scope. The demo stays linear: Why → Spec → Tests → Implementation; the engine and monitor support general graphs and cycles.
Keep actual provider evaluation and runtime execution; never fabricate recorded review results. Use Node's built-in test runner. Do not commit authentication data, SQLite state, worktrees or raw provider event logs.
