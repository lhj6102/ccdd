# CCDD 6.1.0 — Shared review management

This release implements [review management #63](https://github.com/lhj6102/ccdd/issues/63)
and updates Pi AI and Agent Core together to 0.87.1. Install matching packages:

```sh
npm install --ignore-scripts @ccdd/core@6.1.0 @ccdd/project@6.1.0 @ccdd/default-tools@6.1.0
```

Node.js 22 LTS (22.19.0 or later) remains required. Default-tools is optional for
custom-tool-only consumers. Project and default-tools require core `>=6.1.0 <7`.
Core adds owner identity weights, root review policy and pinned script execution
paths. The aligned minimum avoids claiming unverified mixed-version support;
it does not mean every old default-tool operation necessarily fails.

## Review-management changes

- A shared SQLite authority coordinates provider/model/repository executor slots
  across processes and repositories using the same machine roots. FIFO identity
  admission sums declared weights against local capacity. Dead-owner recovery,
  tracked child cleanup and cancellation retain slots until owned work stops.
- `maxExecutions` / `--max-executions` is a durable submission budget. Preflight
  rejects immediately executable excess; atomic admission reserves an attempt
  and capacity before start. Reuse/coalescing consume no start. Started or
  ambiguously started attempts do not refund; known prestart cancellation does.
- Root `reviewPolicy` unifies default dependency gates and optional repository
  caps. Multi-root selections share one deduplicated submission budget. SCC,
  RED-to-BLOCKED and ERROR-to-WAIT_DEPENDENCY semantics remain explicit.
- Declared runtime paths are captured and pinned. Results, compact references,
  changes and attempt ledgers expose structural digests separately from raw
  regular-file SHA-256. Reuse retains original provenance; missing history is
  `null`. This launch contract is not an OS sandbox against hostile scripts.
- `load-check` uses actual registered tools with synthetic reviewers, guarded
  Node processes and isolated diagnostic state. Single/multiple-process and
  real-project scenarios expose tool latency, event-loop delay and throughput.
  Synthetic GREEN never becomes normal review evidence. Guards cover their
  documented Node APIs/imports, not arbitrary native network operations.

See [review management](../review-management.md) for settings, APIs and boundaries.

## Upgrade requirements

**Stop all 6.0 workers before upgrading.** The new worker protocol is
`resources-1`; old saved workers/Runs cannot resume or join new active execution.
Completed format-6 evidence remains readable and reusable; do not delete state
or edit its format marker. Missing historical provenance remains unknown.

`identityConcurrency` / `--identity-concurrency` now fails with migration guidance:
use machine `identityCapacity` and Artifact `stale.weight` instead. Executor
concurrency can only tighten machine caps. Share the same configuration and
machine state root across repositories; use `--state-dir` to separate review
history. No package/Pi/resource-setting salt is added to semantic identities;
explicit reviewed configuration edits still change file-hash inputs normally.
Follow [the upgrade sequence](../releases.md#upgrading-to-61).

## Pi and transport

The native catalog includes `openai-codex/gpt-6-luna` with `xhigh` and
`opencode-go/deepseek-v4.1-flash` with `low`, `high` or `max`. Unsupported effort
is rejected, never silently mapped. Native OpenCode headers preserve the review
session through tools and one JSON-format repair and identify Pi truthfully.
Normalized transcript, finish-turn and image-environment APIs are updated;
explicit authentication adapters remain read-only.

Pi's Codex Responses parser already omitted server `response.model` in 0.85.1
and still does in 0.87.1. Missing metadata is **unknown**, not server-model
attestation. CCDD rejects explicit mismatches that Pi exposes; no parallel SSE
parser or model alias was added. See [the limitation](../../src/executors/CONTEXT.md#provider-identity-visibility).

  passed 549 tests with zero failures/skips, plus production package smoke checks.
  Its prestart-cancellation regressions prove no executor call and a refunded

  multiple processes with actual local tools. A real-project 180-Critic scenario
  on runtime `60d05fea` completed 180 synthetic reviews and 720 tool calls with
  zero errors. Later temp-isolation and prestart fixes were covered by targeted
  tests and the final full suite; that 180 scenario was not rerun at the final
  runtime commit. These are diagnostic observations, not model-quality evidence
  or a measured performance improvement.
- Production tarballs built from `e26562cb` completed one real Luna/xhigh smoke
  review in about 6.04 seconds, with one successful registered tool call, valid
  GREEN JSON (`observedSum: 5`), two completed assistant messages and no format
  repair. One attempt started and terminated; a `maxExecutions: 0` submission
  reused its original provenance with zero starts. Recorded raw hashes matched
  declared/captured runtime bytes and no machine leases remained after close.
- The initial smoke driver exited 1 because it incorrectly expected a temporary
  tool receipt to survive normal Runner cleanup. The original logs/summary were
  preserved. A separate audit-only verifier exited 0 against persisted results,
  tool events, attempt/provenance, reuse and lease records, with no additional
  Provider call. The deleted transient receipt was not observed after close or
  recreated. This harness correction is not a hidden successful rerun.

The live smoke is one benign review, not a throughput, cap-saturation or quality
benchmark. Assistant messages are not an HTTP retry count. No live OpenCode Go
trial was performed for this release gate. Release CI verifies the exact merged
commit and the packages later published by OIDC; local smoke tarballs are evidence,
not a substitute for those CI artifacts.
