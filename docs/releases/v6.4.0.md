# CCDD 6.4.0 — Reviewer result checks

This release adds a way to check an Agent Critic's final result against the tool
calls the reviewer actually made, and several changes that make reviewer tools
smaller and easier to tune.

## Result checks

An Agent Critic may declare `resultCheck`:

```json
{ "id": "evaluate", "profile": { "kind": "agent" }, "resultCheck": { "script": "checks/result.mjs", "timeoutMs": 30000 } }
```

The owner-relative Node script receives the result and the successful tool calls
in order, and prints `{"errors":[...]}`. A nonempty list reuses the existing single
repair turn, which has no tools; a second failure is `PROVIDER_RESULT_INVALID`. A
script that cannot run, exits nonzero, times out or prints anything else fails the
review with `RESULT_CHECK_FAILED`. The script is trusted owner code, not a sandbox.
See [contracts](../contracts.md) for the exact contract. Human and Runtime Critics
cannot declare it.

## Reviewer tools and schemas

- [Designing reviewer tools](../reviewer-tools.md) is a new guide for keeping tool
  definitions and outputs small, with a ready-to-paste agent brief.
- Repair turns name the failing field and keyword: the verdict's GREEN or RED
  branch, const-discriminated branches and `allOf` indexes.
- Tool and response schemas accept `contains` with `minContains` and `maxContains`.
- `tools check --critic ARTIFACT/ID` reports a Critic's static prompt size without
  calling a Provider.

## Fixes

- The shared environment-script executor now settles after its kill grace even when
  detached descendants hold its pipes. It does not kill those descendants.
- Identity script output cleanup failures report the fixed identity error instead
  of local paths or file system text.
- A test reads child pids as plain text, so it no longer hangs under `FORCE_COLOR`.

## Identity

Existing review identities do not change. `resultCheck` is omitted from the stored
request envelope when it is not declared, and the golden Critic hash and request key
tests pass unchanged. A declared `resultCheck` script is an identity input: changing
it invalidates default and `file-hash` identities, so adding one to a Critic
requires a new review of that Critic.

## Compatibility

Four packages are aligned at 6.4.0 with the existing core peer floor `>=6.1.0 <7`
unchanged. Project 6.4.0 does not import `@ccdd/core` and bundles its own
`resultCheck` validation and execution, so it needs nothing new from core 6.4.0.
Only the `ResultCheck` type for TypeScript authors arrives with core 6.4.0; use
matching versions if you type manifests with it.
