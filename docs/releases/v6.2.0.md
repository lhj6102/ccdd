# CCDD 6.2.0 — Single install and Pi API access

This release makes exactly two additions: one installation package for the
existing CCDD modules, and unchanged public access to the Pi AI library already
used by CCDD. No new authentication CLI, credential store, connection registry,
provider precedence policy or coding-agent dependency is introduced.

## Install once

```sh
npm install --ignore-scripts @ccdd/ccdd@6.2.0
# or
pnpm add --ignore-scripts @ccdd/ccdd@6.2.0
```

The umbrella depends normally on core, Project and default-tools **6.2.0**, plus
Pi AI **0.87.1**. No peer auto-install setting or lifecycle script is required.
The modules remain separate; advanced direct-module consumers can still omit
default-tools. Project/default-tools retain their core peer floor `>=6.1.0 <7`:
no new core contract requires raising it for this packaging-only release.

| Public import | Existing implementation |
| --- | --- |
| `@ccdd/ccdd` or `@ccdd/ccdd/core` | Core definitions |
| `@ccdd/ccdd/project` | Project, Broker and executor APIs |
| `@ccdd/ccdd/tools` | Common tools and scriptRequest |
| `@ccdd/ccdd/pi` | Pi AI root exports, unchanged |
| `@ccdd/ccdd/pi/providers/all` | Pi built-in provider/catalog exports, unchanged |

The `ccdd`, `ccdd-project` and `ccdd-view` bins delegate to existing public module
entrypoints. There is no copied command parser, monolithic runtime or automatic
tool registration. Public imports and bins work with only the umbrella declared,
including strict pnpm without hoisting or automatic peer installation.

## Existing Pi authentication APIs

```js
import { builtinModels } from '@ccdd/ccdd/pi/providers/all';
const models = builtinModels();
const providers = models.getProviders();
```

The returned Pi object exposes its existing getModels/getModel/checkAuth/login/
logout/streamSimple methods. Authentication semantics and CredentialStore
injection remain Pi's existing API, not a new CCDD management service.

The official CLI is unchanged:

```sh
npx @earendil-works/pi-ai@0.87.1 list
npx @earendil-works/pi-ai@0.87.1 login [provider]
```

That CLI selects OAuth providers and writes `auth.json` in its current directory;
use an appropriate private directory outside review input. Its library supports
API-key login, but the current bundled CLI does not expose it. No real keys belong
in command examples, repository input or logs. Existing read-only external Codex
adapter behavior is unchanged. Pi's known Codex response-model metadata omission
also remains unchanged; absent metadata is not server-model attestation.

## Verification and publication

The implementation passed 553 tests without failures/skips and 22 focused release
tests. Production verification covers direct-module default/custom configurations
and sole-umbrella npm/strict-pnpm installs: public ESM/type imports, forwarded bins
and error exit/stdout, actual default/custom tools, Runtime GREEN and reuse-only
execution. Pi accessibility checks inspect static catalogs and method types only;
they never log in, resolve credentials or call a model, and block fetch.

The final version/docs-only commit reuses unchanged-source test evidence and
re-verifies exact committed archives and installed consumers. Main CI reruns the
full suite and creates the only production artifacts. No extra real model call
is needed for these two additions. Existing state, review identity, resource
admission, profiles and tool/schema behavior are not changed.

All four CCDD packages participate in checksum/integrity validation. Normal
publication is dependency-first; retries skip only identical published bytes and
reject any mismatch before the first write. The new umbrella requires its own
npm Trusted Publisher bootstrap: only the final reviewed CI tarball may be first
published by an authorized maintainer, then bound to the existing workflow. Never
publish a placeholder or development build. Installation is ready only after all
exact dependencies are published. See [the bootstrap procedure](../releases.md#first-publication-of-the-umbrella).
