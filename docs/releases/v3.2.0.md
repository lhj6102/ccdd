# CCDD v3.2.0

CCDD 3.2.0 adds generated Artifacts with fixed, persisted JSON data and
versioned identity strategies. Equivalent generated review inputs can reuse
applicable actual GREEN evidence without another review. All three packages
release together: `@ccdd/core`, `@ccdd/project`, and `@ccdd/default-tools`.

## Changes

- Register Artifact sources explicitly with `defineArtifactSource`. Preparation
  captures the complete observable data separately from configuration loading
  and review execution.
- Choose canonical-data, immutable-revision, or custom fingerprints with an
  explicit namespace and version. Existing file identities and group composition
  retain their behavior.
- Register selective observation tools with `defineDataTool`. Tools read a copy
  of their bound data through `context.readData()`; initial Agent prompts and
  monitor metadata do not contain the captured corpus.
- Persist the data and its integrity hash for worker restart, MCP tools, and
  remote Human preparation. Reopening never regenerates from the live source.
- Preserve historical GREEN reuse, latest-RED precedence, dependency gates,
  conservative configuration hashing, and the request-scoped `always` policy.
- Keep monitor/history GETs observational. Current-input queries accept only
  sources declaring read-only preparation; sources requiring generation must
  be prepared through an explicit verification or diagnostic action.

## Install and upgrade

```sh
npm install --ignore-scripts @ccdd/core@3.2.0 @ccdd/project@3.2.0 @ccdd/default-tools@3.2.0
```

Node.js 22 LTS (22.19.0 or later) is required. Default tools are optional when
all tools are custom. Existing file-based configurations and stored reviews
remain compatible without migration. Install matching package versions to use
the new source and data-tool helpers.

Generated data supports Agent and Human Critics, including groups and direct
dependencies. Each Artifact is limited to 4 MiB of canonical UTF-8 JSON and
64 nested containers. Runtime Critics retain their filesystem contract and
explicitly reject generated Artifact scopes.

See the [generated Artifact guide](https://github.com/lhj6102/ccdd/blob/v3.2.0/docs/generated-artifacts.md) and
[two-scenario example](https://github.com/lhj6102/ccdd/blob/v3.2.0/examples/generated-artifacts/README.md) for source
definitions, canonicalization, identity assertions, and selective tools.
