# CCDD v3.3.1

CCDD 3.3.1 reduces repeated generated Artifact tool-call overhead. All three
packages release together: `@ccdd/core`, `@ccdd/project`, and
`@ccdd/default-tools`.

## Changes

- Register each captured generated Artifact once with its private tool host,
  validating its snapshot definition, source identity, and full content hash.
- Send the bound Artifact ID on subsequent tool calls instead of transporting
  and validating the complete data again. Tools that do not call `readData()`
  avoid copying it; each `readData()` still returns an independent clone.
- Keep bindings within one host lifetime. Fresh hosts validate their own
  snapshots, including changed content under the same logical Artifact ID.

## Performance evidence

Three alternating benchmark pairs using content integrity and 65,682-byte
inputs reduced median warm constant-return calls from 8.31 ms to 1.23 ms,
and calls using `readData()` from 9.63 ms to 2.69 ms. Host setup is measured
separately. A consuming application's 1,953-call comparison reduced tool-call
time from 9.40 s to 3.89 s with unchanged normalized observations.

These are offline tool-path measurements, not model-review latency or verdict
evidence. See the [benchmark method, raw timings, and limits](../generated-tool-performance.md).

## Install and upgrade

```sh
npm install --ignore-scripts @ccdd/core@3.3.1 @ccdd/project@3.3.1 @ccdd/default-tools@3.3.1
```

Node.js 22 LTS (22.19.0 or later) is required. Default tools remain optional
when all tools are custom. Existing configurations and stored reviews remain
compatible without migration. Active reviews retain their original snapshots;
restart an active monitor with the new CLI after upgrading.

## Verification

Registry tests cover repeated and concurrent calls, preflight and tool mutation
isolation, caller input and output edits, and new snapshots under the same ID.
Existing corruption, missing-data, restart, Agent, MCP, and remote Human coverage
remains in the suite.

CI verifies the release commit and production-package installations before
publication. CD publishes those exact tarballs through npm Trusted Publishing.
See the [release guide](../releases.md) for publication and recovery.
