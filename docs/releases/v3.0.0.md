# CCDD v3.0.0

Human reviewers can work from another computer by downloading the complete fixed
project and running its registered tools locally. All three packages release
together at 3.0.0: `@ccdd/core`, `@ccdd/project`, and `@ccdd/default-tools`.

## Remote Human review

- `ccdd-project review serve` exposes authenticated snapshot downloads and Human
  assignment/result actions for one existing project store.
- The reviewer CLI lists and shows requests, prepares claims, runs tools locally,
  and submits actual Human judgments to the original Broker.
- Verified files are cached by content hash. Later snapshots download only missing
  content and retain independent immutable copies of earlier reviewed inputs.
- `human.project.open()` launches an application bundled in the project, with
  private writable configuration and the reviewer's desktop connection settings.
  Declared runtime file hashes participate in the tool's review conditions.

## Try Claim and environment checks

Claiming first enters **Try Claim**, an exclusive expiring reservation. The client
prepares the snapshot, runs the project's `envRequirements` scripts, and checks
registered Human tools. Only successful preparation confirms **Claim**.

Failed downloads, environment checks, or cancellation release the attempt and
return a preparation diagnostic. They do not fabricate a verdict or mark the
entire review request as ERROR. Attempt identities and renewal expiry prevent
late responses from overwriting another reviewer's reservation. The local CLI
and monitor use the same preparation contract.

New tool manifests use locale-independent module ordering. Verified historical
manifests reconnect using their recorded order only after the current module
hashes and full configuration hash are checked.

## Breaking SDK change and upgrade

`Broker.claimHuman()` is now asynchronous because it performs real preparation.
SDK callers must await it before invoking a tool or submitting a result:

```ts
await broker.claimHuman(requestId, reviewerId);
await broker.executeHumanTool(requestId, { reviewerId, toolName, arguments: {} });
```

CLI command names for existing local Human workflows remain available. Existing
review snapshots and actual evidence are retained. New verification uses the
installed executor version when deciding whether prior evidence is reusable.

Upgrade the coordinated package versions together:

```sh
npm install --ignore-scripts @ccdd/core@3.0.0 @ccdd/project@3.0.0 @ccdd/default-tools@3.0.0
npx ccdd-project config check
npx ccdd-project tools check
```

Use only core and Project if all your tools are custom. Node.js 24 or later is
required. Remote publisher and reviewer clients must use the same Project
version. Remote transfer supports copy-mode TS configurations; the local
loopback monitor and local lock-mode review keep their existing roles.

See [remote Human review](../remote-human-review.md) for credentials, bundled
applications, environment scripts, supported platform conditions, and usage.
