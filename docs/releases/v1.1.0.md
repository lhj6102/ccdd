# CCDD v1.1.0

이미지를 실제로 관측하는 기본 Agent 도구와, 독립 Artifact들을 하나의 검토 단위로 묶는 Artifact 그룹을 추가합니다. 본체와 선택형 기본 도구 라이브러리를 함께 1.1.0으로 배포합니다.

## 주요 변경

- **이미지 기본 도구:** `agentTools: { view_image: agent.image.view() }`로 명시적으로 등록합니다. `view_image_<Artifact ID>`는 Pi의 `createReadTool()`을 재사용하여 실제 PNG/JPEG/WebP 이미지 블록을 반환합니다. 파일 내용으로 형식을 판별하며 최대 4MiB입니다. 별도 LLM 호출이나 Agent 세션을 만들지 않습니다.
- **Artifact 그룹:** `explosion: { kind: 'group', members: ['effect', 'preview'] }`처럼 독립 ID를 참조합니다. 다른 그룹도 재귀적으로 포함할 수 있으며 알 수 없는 구성원·중복·구성 순환은 거부합니다. 그룹에는 타입과 경로가 없습니다.
- **독립적인 판정과 의존성:** 그룹과 멤버 모두 `target`·`deps`로 선택할 수 있습니다. 판정은 각 대상을 직접 평가하는 Critic들만 집계합니다. 구성 관계 자체는 선행 검증 조건이 아니며, 멤버 검증 후 그룹을 평가하려면 해당 멤버를 `deps`에 명시합니다.
- **도구·지시사항·모니터 연결:** 그룹 범위를 개별 Artifact로 펼쳐 공유 멤버의 도구를 한 번만 제공합니다. Agent는 모든 개별 Artifact를 관측해야 합니다. `{explosion}`은 Agent에게 멤버별 도구 목록으로, Human에게 도구 선택 버튼으로 표시됩니다. Graph에서는 구성원과 소속 그룹을 탐색하며 구성 관계를 검증 의존 간선과 구분합니다.
- **진단과 예제:** `tools check --artifact GROUP`으로 구성원의 도구를 검사하고, 실제 실행은 개별 Artifact와 도구를 지정합니다. 이미지와 문서를 묶는 `examples/artifact-groups` 예제를 배포 패키지에 포함합니다.

이미지 도구는 자동 축소·변환을 하지 않습니다. GIF·BMP·animated PNG 및 텍스트만 반환되는 입력은 실패합니다. 디렉터리 Artifact에서는 내부 파일 `path`를 지정하며, Agent 리뷰에는 이미지 입력을 지원하는 모델이 필요합니다.

## 설치

Node.js 24 이상에서 Release의 `lhj6102-ccdd-1.1.0.tgz`와 `lhj6102-ccdd-default-tools-1.1.0.tgz`를 내려받고 체크섬을 확인한 뒤 리뷰 대상 프로젝트에 설치합니다. 사용자 도구만 사용한다면 본체만 설치합니다. TS 설정을 사용하는 프로젝트는 `package.json`의 `type`을 `module`로 지정합니다.

## 기존 설정과 호환성

v1.0.0의 개별 Artifact 설정은 변경 없이 사용할 수 있습니다. 그룹과 이미지 도구는 선택하여 추가하며, 설치하거나 import하는 것만으로 등록되지 않습니다. 기존 leaf-only 요청은 그룹 필드를 추가하지 않고 원래 형태를 유지합니다.

진행 중인 리뷰·Human 대기·판정·snapshot은 당시의 설정과 도구 범위를 유지합니다. 새 패키지는 원본 프로젝트에 설치하여 이후 요청부터 사용하고, 모니터는 새 CLI로 다시 시작합니다. 기존 데모는 보존하며 새 버전은 비어 있는 `--demo-dir`에서 준비합니다.

v1.0.0 이전 설정에서 업그레이드한다면 [기존 설정 이전 안내](https://github.com/lhj6102/ccdd/blob/v1.0.0/docs/releases/v1.0.0.md#기존-설정에서-이전)도 확인하세요.

## 검증 범위

로컬 Release 명령은 지정한 커밋을 임시 clone에 재현하여 빌드·전체 테스트, 두 tarball의 별도 설치·도구 실행·Runtime을 검증합니다. 소스 커밋과 검증 환경은 첨부된 `verification.json`, 파일 무결성은 `SHA256SUMS`로 확인할 수 있습니다.

배포 검증은 외부 LLM을 호출하지 않습니다. 실제 Provider·모델 접근은 설치 환경의 `ccdd doctor`로 확인하고, 사용자 도구와 데스크톱 연결은 `ccdd tools check`와 선택한 도구의 `--execute`로 확인합니다.
