# CCDD v1.1.0

This release adds a default Agent tool that observes actual images and Artifact groups that combine independent Artifacts into one review unit. The main package and optional default tool library are released together as 1.1.0.

## Main changes

- **Default image tool:** Explicitly register `agentTools: { view_image: agent.image.view() }`. `view_image_<Artifact ID>` reuses Pi's `createReadTool()` to return actual PNG/JPEG/WebP image blocks. Formats are detected from file content, with a 4MiB limit. It creates no separate LLM call or Agent session.
- **Artifact groups:** Reference independent IDs, for example `explosion: { kind: 'group', members: ['effect', 'preview'] }`. Groups can recursively contain other groups; unknown members, duplicates, and membership cycles are rejected. Groups have no type or path.
- **Independent verdicts and dependencies:** Both groups and members can be selected as `target` or `deps`. Verdicts aggregate only Critics directly evaluating each target. Membership alone is not a validation prerequisite; to evaluate a group after member validation, explicitly put those members in `deps`.
- **Tools, instructions, and monitor integration:** Group scopes expand to individual Artifacts, supplying shared members' tools only once. Agents must observe every individual Artifact. `{explosion}` displays each member's tool list to Agents and tool selection buttons to Humans. Graph supports navigation through members and containing groups while distinguishing membership from validation dependency edges.
- **Diagnostics and example:** Use `tools check --artifact GROUP` to check member tools; select an individual Artifact and tool for actual execution. The distributed package includes `examples/artifact-groups`, which groups an image and a document.

The image tool does not automatically resize or convert images. GIF, BMP, animated PNG, and inputs that return only text fail. Directory Artifacts require an internal file `path`, and Agent reviews need a model that accepts image input.

## Installation

On Node.js 24 or later, download `lhj6102-ccdd-1.1.0.tgz` and `lhj6102-ccdd-default-tools-1.1.0.tgz` from the Release, verify checksums, and install them in the project to review. If you use custom tools exclusively, install only the main package. Projects using TS configuration must set `type` to `module` in `package.json`.

## Existing configuration and compatibility

Individual Artifact configurations from v1.0.0 work unchanged. Groups and image tools are optional additions; installing or importing them does not register them. Existing leaf-only requests retain their original shape without added group fields.

Active reviews, Human waits, verdicts, and snapshots retain their original configuration and tool scope. Install new packages in the original project for subsequent requests, and restart the monitor with the new CLI. Existing demos are preserved; prepare the new version in an empty `--demo-dir`.

When upgrading from configuration older than v1.0.0, also see the [configuration migration guide](https://github.com/lhj6102/ccdd/blob/v1.0.0/docs/releases/v1.0.0.md#%EA%B8%B0%EC%A1%B4-%EC%84%A4%EC%A0%95%EC%97%90%EC%84%9C-%EC%9D%B4%EC%A0%84).

## Verification scope

The local Release command recreates the specified commit in a temporary clone and verifies the build, full test suite, and separate installation, tool execution, and Runtime behavior of both tarballs. The attached `verification.json` identifies the source commit and verification environment; `SHA256SUMS` verifies file integrity.

Release verification calls no external LLM. Check actual Provider and model access with `ccdd doctor` in the installation environment, and check custom tools and desktop connections with `ccdd tools check` and the selected tool's `--execute`.
