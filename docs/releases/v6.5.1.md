# CCDD 6.5.1 — Ordered budget counting and per-request usage

## Tool-call budget counts by issue order

`maxToolCalls` links calls by the order the model issues them, not by Provider
tool-call ids. Pi's sequential executor announces every call with
`tool_execution_start`, in source order, before resolving its name or preparing
arguments. Unknown names and invalid arguments still count.

A malformed batch that reuses one id no longer rejects an in-budget call. With
`maxToolCalls: 1` and two calls sharing an id, the first call runs, the second is
refused, and the review ends with `PROVIDER_BUDGET_EXCEEDED`. This fixes the
[6.5.0 limitation](v6.5.0.md#known-limitation) tracked in
[issue #84](https://github.com/lhj6102/ccdd/issues/84) and fixed in
[PR #86](https://github.com/lhj6102/ccdd/pull/86).

Behavior without a tool-call budget is unchanged. `maxTokens`, cancellation and
deadline precedence are unchanged. See the [review-budget contract](../contracts.md#review-budget).

## Per-request usage totals

Full request views (`run show RUN_ID --json`, `projectRun`, full Broker views)
expose `usage` for every status, independently of the Run's latest-500-event
window. Each counter sums Pi's reported usage for the request's current attempt:
`input`, `output`, `cacheRead`, `cacheWrite`, `cacheWrite1h`, `reasoning` and
`totalTokens`.

- Each accepted `executor.usage` event adds to a separate `request_usage` table,
  keyed by request id and `attemptId`.
- The event and its attempt sum are written in the same transaction: both commit
  or neither does.
- A retry starts a new sum. Cancelled and failed attempts retain accepted usage
  up to their existing event-acceptance boundary.
- Compact views omit `usage`. Requests without recorded usage have no sum; reused
  evidence, Runtime execution and older reviews do not acquire invented totals.
- Missing counters remain absent. `reasoning` is part of `output`, and
  `cacheWrite1h` is part of `cacheWrite`; do not add every counter as though they
  were disjoint. `totalTokens` is Pi's reported total, not a computed cost.

The event window and metadata-only telemetry rules are unchanged. See
[PR #87](https://github.com/lhj6102/ccdd/pull/87) and the
[execution telemetry contract](../contracts.md#execution-telemetry).

## State and downgrade

The state format stays 6. A writable Broker adds `request_usage` with
`CREATE TABLE IF NOT EXISTS`. Read-only readers of state without the table read
empty usage, without requiring a migration or fresh state directory.

Downgrading to 6.5.0 or 6.4 ignores the table and may leave hidden rows after a
retry or completion. On returning to 6.5.1, a sum is shown only when its stored
attempt id matches the request's current `attemptId`; an earlier attempt's sum
is never shown as the current attempt's usage.

## Identity

Existing review identities are unchanged; the golden identity tests pass without
modification. Budget declarations remain identity inputs as in 6.5.0. Usage is
execution telemetry, never part of Artifact/SCC hashes, ValidationInput or reuse
keys.

## Compatibility

Four packages are aligned at 6.5.1 with the core peer floor `>=6.1.0 <7`
unchanged. Both changes are implemented in Project's bundled Executor and Broker
code. Project does not import `@ccdd/core`, and 6.5.1 adds no core definitions or
runtime requirements, so it needs nothing newer from core. Use matching package
versions for the supported installation.
