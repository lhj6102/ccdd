# CCDD v1.0.0

CCDD의 Critic 중계·Artifact Runner와 로컬 모니터를 1.0으로 묶습니다. 마지막 배포인 v0.7.0 이후의 변경을 포함하며, 본체와 선택형 기본 도구 라이브러리를 각각 설치할 수 있습니다.

## 주요 변경

- **Artifact DAG:** Critic이 `target` 하나와 `deps` 배열을 선언합니다. 한 Artifact의 필수 Critic이 모두 통과하면 그 Artifact에 의존하는 검토가 시작됩니다.
- **Kanban / Graph 모니터:** 프로젝트와 검증 실행을 선택하고 Artifact 관계·Critic 종류·판정을 봅니다. Vue Flow와 ELK로 연결과 배치를 표현하며 Human claim·도구 실행·판정 제출은 같은 요청 상세에서 이어집니다.
- **TypeScript 설정과 사용자 도구:** `ccdd.config.ts`에서 도구의 metadata·입력 Schema·execute·선택적 preflight를 직접 등록합니다. 도구 명세는 기록에 저장하고 구현은 요청과 같은 snapshot에서 다시 연결합니다.
- **별도 기본 도구 라이브러리:** `@lhj6102/ccdd-default-tools`를 선택하여 설치합니다. Agent는 CLI 읽기·목록, Human은 데스크톱 프로그램 열기를 사용하며 등록은 config에서 명시합니다.
- **지시사항의 Artifact 참조:** `{spec}`을 Agent에게 Artifact ID와 실제 도구 목록으로 전달하고, Human에게 해당 도구 영역으로 이동하는 버튼으로 표시합니다. 저장 문자열과 요청·HTTP API는 유지하며 범위 밖 참조는 원문으로 남습니다.
- **자동 Release:** 검증을 통과한 두 tarball과 체크섬·설치 검증 기록을 GitHub Release에 게시합니다. 본체·기본 도구 패키지 버전은 함께 관리합니다.

Git commit이나 상주 daemon 없이 `--copy`·`--lock`으로 리뷰하고, Agent·Human·Runtime 실행기를 분리하는 구조는 유지합니다. 모니터는 선택 사항이며 종료해도 실행 작업이나 Human 대기 기록이 사라지지 않습니다.

## 설치

Node.js 24 이상이 필요합니다. 이 비공개 저장소에 접근할 수 있는 계정으로 Release의 `lhj6102-ccdd-1.0.0.tgz`와 `lhj6102-ccdd-default-tools-1.0.0.tgz`를 내려받고 체크섬을 확인한 뒤, 리뷰 대상 프로젝트에 로컬 설치합니다. 사용자 도구만 작성한다면 본체만 설치합니다.

## 기존 설정에서 이전

- `dependsOn`과 Critic의 `artifacts` 대신 `target`·`deps`를 선언합니다. 검증의 출발점인 Artifact는 `basis: true`로 명시합니다. [Artifact 의존 관계 안내](https://github.com/lhj6102/ccdd/blob/v1.0.0/docs/artifact-graph.md)를 참고하세요.
- 신규 설정은 `ccdd.config.ts`를 사용합니다. 기본 도구도 `agent.text.read()`·`human.desktop.open()`처럼 명시적으로 등록합니다. 기존 JSON의 Viewer·기본 도구 설정은 이전을 위한 호환 경로로 남지만, 위의 Critic 의존 관계는 변경해야 합니다. JSON과 TS 설정을 함께 두면 충돌 오류입니다.
- TS config가 import하는 패키지는 리뷰할 프로젝트의 `node_modules`에 설치합니다. 전역 CLI나 상위 저장소의 의존성으로 대체하지 않습니다.
- Agent·Human 도구는 각각 등록합니다. 해당 종류의 도구가 없는 Artifact는 그 종류의 Critic에서 사용할 수 없습니다. 기본 Human `open`은 macOS 연결을 사용하며 다른 OS에서는 `command`와 필요한 고정 `args`를 지정합니다. 프로그램을 연 사실만으로 관측이나 판정 완료로 처리하지 않습니다.
- 기존 데모는 파일과 설치된 패키지를 보존합니다. 새 두 tarball로 시험하려면 비어 있는 `--demo-dir`를 지정합니다. 기본 `demo-v9` 이름은 데모 형식 버전이며 패키지 버전과 별개입니다.

기존 요청·판정·관측 기록과 snapshot은 유지합니다. 과거 기록을 새 설정이나 도구로 다시 해석하지 않으며, Graph 정보가 없는 과거 실행은 Kanban에서 확인할 수 있습니다.

## 검증 범위

자동 Release는 Node 24·Ubuntu에서 빌드·전체 테스트와 배포 tarball의 별도 설치·실행을 확인합니다. 그 실행의 정보는 첨부된 `verification.json`, 파일 무결성은 `SHA256SUMS`로 확인할 수 있습니다.

CI는 외부 LLM을 호출하지 않습니다. 실제 인증·모델 접근은 설치 환경에서 `ccdd doctor`로, 사용자 Artifact 도구와 데스크톱 연결은 `ccdd tools check` 및 선택한 도구의 `--execute`로 확인합니다. `doctor`와 Agent 리뷰는 해당 Provider의 사용량을 소비합니다.
