# CCDD v1.0.0

This 1.0 release brings together CCDD's Critic brokering, Artifact Runner, and local monitor. It includes changes since the previous release, v0.7.0, with separate installation of the main package and optional default tool library.

## Main changes

- **Artifact DAG:** Critics declare one `target` and a `deps` array. When all required Critics for an Artifact pass, reviews depending on that Artifact can start.
- **Kanban / Graph monitor:** Select a project and validation execution to view Artifact relationships, Critic kinds, and verdicts. Vue Flow and ELK display connections and layout; Human claim, tool execution, and verdict submission continue in the same request detail.
- **TypeScript configuration and custom tools:** Register tool metadata, input schemas, execute functions, and optional preflight checks directly in `ccdd.config.ts`. Tool manifests are stored in history, and implementations reconnect from the same snapshot as the request.
- **Separate default tool library:** Optionally install `@lhj6102/ccdd-default-tools`. Agents use CLI reading and listing; Humans open desktop applications. Registration is explicit in configuration.
- **Artifact references in instructions:** `{spec}` gives Agents an Artifact ID and actual tool list, and gives Humans a button that navigates to those tools. Stored strings and request/HTTP APIs are preserved; out-of-scope references remain literal.
- **Local releases from a commit:** Fix the source to release with `npm run release -- --commit <40-character SHA>`. Publish the two tarballs verified in a temporary clone, together with checksums and installation verification records, to GitHub Releases. Main and default-tools package versions are managed together.

The architecture still supports `--copy` and `--lock` reviews without a Git commit or resident daemon, with separate Agent, Human, and Runtime Executors. The monitor is optional; closing it does not remove active work or Human waiting records.

## Installation

Node.js 24 or later is required. Using an account with access to the private repository at the time of this release, download `lhj6102-ccdd-1.0.0.tgz` and `lhj6102-ccdd-default-tools-1.0.0.tgz`, verify checksums, and install them locally in the project to review. If you write only custom tools, install the main package alone.

## Migrating existing configuration

- Declare `target` and `deps` instead of `dependsOn` and Critic `artifacts`. Explicitly mark validation starting points with `basis: true`. See the [Artifact dependency guide](https://github.com/lhj6102/ccdd/blob/v1.0.0/docs/artifact-graph.md).
- Use `ccdd.config.ts` for new configuration. Explicitly register default tools too, such as `agent.text.read()` and `human.desktop.open()`. Existing JSON Viewer and default-tool configuration remains a migration compatibility path, but the Critic dependencies above must be updated. Keeping JSON and TS configuration together causes a conflict error.
- Install packages imported by TS configuration in the reviewed project's `node_modules`. Do not substitute a global CLI or parent repository dependencies.
- Register Agent and Human tools separately. An Artifact without tools for an audience cannot be used by that kind of Critic. Default Human `open` uses macOS associations; on other systems, specify `command` and any fixed `args` needed. Opening a program alone is not treated as a completed observation or verdict.
- Existing demos retain their files and installed packages. To test the two new tarballs, specify an empty `--demo-dir`. The default `demo-v9` name is a demo format version, separate from the package version.

Existing requests, verdicts, observation records, and snapshots are preserved. Historical records are not reinterpreted using new configuration or tools; historical runs without Graph information remain available in Kanban.

## Verification scope

The local Release command recreates the specified commit in a temporary clone and checks the build, full test suite, and separate installation, tool execution, and Runtime behavior of distribution tarballs on Node 24 or later. The attached `verification.json` identifies that execution's source commit and environment; `SHA256SUMS` verifies file integrity. `--dry-run` performs all verification and file generation without GitHub authentication.

Release verification uses neither GitHub Actions nor external LLMs. Check actual authentication and model access in the installation environment with `ccdd doctor`; check custom Artifact tools and desktop connections with `ccdd tools check` and the selected tool's `--execute`. `doctor` and Agent reviews consume the relevant Provider's usage.
