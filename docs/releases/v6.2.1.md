# CCDD 6.2.1 — Remove arbitrary timeout ceilings

Existing `profile.timeoutMs` accepts 1,200,000 milliseconds (20 minutes).
Profile, executor, tool, environment-check, identity and CLI timeout validators
now use positive safe integers up to 2,147,483,647 milliseconds: the technical
Node timer limit, beyond which a timer would overflow rather than wait.

No new execution override, global setting or authentication API is introduced.
Existing defaults, the Agent deadline/timer, cancellation, individual tool timers
and the shared final-repair deadline are unchanged. CLI waiting timeouts remain
separate from declared execution timeouts. Fixed internal safety timers are not
changed.

Four packages are aligned at 6.2.1, with Pi 0.87.1 and the existing core peer floor
unchanged. Review envelopes, identities, provenance and cache rules are unchanged;
consumers remain responsible for which facts their owner identities include.
Tests cover 20-minute acceptance, consistent configuration validation and rejection
of values that would overflow Node timers, without live Provider calls or long waits.
