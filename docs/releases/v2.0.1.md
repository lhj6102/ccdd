# CCDD v2.0.1

Package names move to the `@ccdd` scope for public npm publication. All three package versions are aligned at 2.0.1.

| Previous name | npm name | Role |
| --- | --- | --- |
| `@lhj6102/ccdd` | `@ccdd/core` | Artifact, Critic, and tool definitions |
| `@lhj6102/ccdd-project` | `@ccdd/project` | Project Validation, CLI, Broker, Executors, and monitor |
| `@lhj6102/ccdd-default-tools` | `@ccdd/default-tools` | Optional, explicitly registered default observation tools |

The CLI names remain `ccdd-project` and `ccdd`. Project and default tools use `@ccdd/core >=2.0.0 <3` as a peer dependency.

## Migration

After the new version is published, install matching versions of all three packages and update imports in the original project's `ccdd.config.ts` and custom tools to the new names.

```sh
npm install --ignore-scripts @ccdd/core@2.0.1 @ccdd/project@2.0.1 @ccdd/default-tools@2.0.1
npx ccdd-project config check
npx ccdd-project tools check
```

Saved review snapshots and demos retain packages and configuration under the old names. New demos use the new names; preparing an existing demo again does not automatically replace its internal configuration or dependencies. Historical GitHub Release files and release notes retain the names used at the time.

## Distribution and verification

`release:npm` verifies the full build and tests, actual package installation, tool execution, Runtime, and validation reuse in a temporary clone of the specified commit, then publishes the verified tarballs. `--dry-run` checks the same packages without publishing. After a distribution failure, retrying skips only packages already published with identical bytes.

See the [distribution guide](../releases.md#public-npm-publication) for the procedure and npm organization permission checks. This document's existence does not mean npm or GitHub publication has completed.
