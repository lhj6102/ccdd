# CCDD v2.0.0

CCDD is split into a definition-only SDK for Artifacts, Critics, and relationships, while project validation and execution history move to the new `@lhj6102/ccdd-project` package. Because the CLI installation package changes, all three packages are released together as 2.0.0.

## Main changes

- **Validation computed on request:** `status` and `plan` recursively check DAG dependencies. No per-Artifact staleState is stored, and no changes are propagated to downstream nodes. Memoization exists only within a query.
- **Actual verdict reuse based on input:** If Critic conditions and target/direct dependency hashes match and prerequisite validation is satisfied, the query references an existing actual PASS. If Why changes and Spec is reviewed again but its content is unchanged, Tests and Implementation reviews can be reused. A later actual RED for identical input takes precedence over an older PASS.
- **Artifact stale strategies:** Supports default file hashes, explicit input path lists, and `always` for review on every request. A path list must include all inputs affecting the Artifact's meaning.
- **Individual and recursive validation:** `verify B` requests immediately ready B Critics and reports blocked items as incomplete. `verify B --recursive` includes necessary predecessor validations and creates only ready actual requests. `--force` reviews selected Critics again while preserving prerequisites.
- **Separate storage and monitor:** Actual verdicts and their hashes, executions, and ticket history remain in Project storage outside the repo. Current-input inspection in the monitor uses an explicit button. Automatic GETs do not evaluate configuration, execute tools, or change review state.

## Installation

On Node.js 24 or later, download the Release's core, Project, and default-tools tarballs, verify `SHA256SUMS`, and install them together.

```sh
npm install --ignore-scripts \
  ./vendor/ccdd/lhj6102-ccdd-2.0.0.tgz \
  ./vendor/ccdd/lhj6102-ccdd-project-2.0.0.tgz \
  ./vendor/ccdd/lhj6102-ccdd-default-tools-2.0.0.tgz
npx ccdd-project config check
npx ccdd-project plan implementation --recursive
npx ccdd-project verify implementation --recursive --wait
npx ccdd-project status implementation
```

Install only core and Project when using custom tools exclusively. For definitions alone, only core is needed. This release is not published to the npm registry.

## Migrating from v1

1. Add `@lhj6102/ccdd-project` and update core and default-tools versions together. Keep `defineConfig`/`defineTool` import paths and existing Artifact/Critic configuration. Stale configuration is optional.
2. Use `ccdd-project verify` for the new validation flow. The Project package supplies the existing `ccdd` CLI, and `ccdd run` retains its independent execution contract.
3. State defaults to `~/.local/state/ccdd/<repo-path-hash>/broker.sqlite`. Change it with `--state-dir` or `CCDD_STATE_HOME`; it must stay outside the reviewed repo. Existing executions, snapshots, and Human waits are preserved. Historical reviews without hash evidence remain readable but cannot be reused as PASS evidence for new validation.
4. Restart the monitor with the new CLI. Request follow-up validation for a terminal incomplete execution with a new `verify`. `verify --wait` uses 0=scope satisfied, 1=RED, 2=ERROR, 3=wait timeout, and 4=incomplete.

## Verification scope

The Release process verifies the build, full test suite, and production installation of three tarballs in an isolated clone of the specified commit. Both default-tool and custom-tool configurations test actual tools, Runtime, separate worker execution, and PASS reuse without tickets. The exact source commit, environment, and test results are recorded in the attached `verification.json`.

Check external Provider evaluation and user desktop connections in the installation environment with `ccdd-project doctor` and the selected tool's `tools check --execute`. Performance improvements for large whole-workspace snapshots are outside this release's scope.
