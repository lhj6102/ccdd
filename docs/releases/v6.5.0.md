# CCDD 6.5.0 — Review budgets and error tool-call records

## Review budget

Agent profiles accept two optional positive integers, unset by default:

```json
{"kind":"agent","provider":"anthropic","model":"claude-sonnet-5-5","reasoning":"low","maxToolCalls":40,"maxTokens":400000}
```

- `maxToolCalls` counts every tool call the model makes, including calls with invalid
  arguments and unknown tool names. The first call over the limit is refused and no
  further tool process runs.
- `maxTokens` sums Pi's `totalTokens` after each model turn, including the repair
  turn and cached reads and writes. It is not a cost budget. The turn that crosses
  it ends the review before that turn's tool calls run.
- Exceeding either ends the review with `PROVIDER_BUDGET_EXCEEDED`, an operational
  ERROR, never a verdict. Cancellation and deadlines take precedence.

See [contracts](../contracts.md) and [reviewers](../reviewers.md).

## Tool-call record for ERROR reviews

Full views of an ERROR request (`run show RUN_ID --json`) show `toolCalls` for the
last attempt, plus `toolCallsOmitted` when calls were not recorded. This covers
cancellation, timeouts, Provider failures and worker death.

- The record is bounded to 200 calls and 256 KiB of arguments.
- Calls are stored in a new `tool_call_records` table while the request runs.
  Critic messages and tool output are never stored, and the event stream stays
  metadata-only.
- The record is purged when a request returns a result; `result.toolCalls` is then
  authoritative. A retry purges the earlier attempt's record.

## State and downgrade

The state format stays 6. A writable Broker adds the `tool_call_records` table on
open with `CREATE TABLE IF NOT EXISTS`. Read-only readers of state without the
table read empty records.

Downgrading to 6.4 reads and runs fine but ignores the table. A retry or success
under 6.4 leaves earlier record rows unpurged: harmless and hidden, not corruption.

## Known limitation

A malformed Provider batch that reuses one tool-call id can reject an in-budget
call ([issue #84](https://github.com/lhj6102/ccdd/issues/84)). It fails closed;
valid Providers use unique ids.

## Identity

Existing review identities are unchanged; the golden identity tests pass without
modification. `maxToolCalls` and `maxTokens` are identity inputs like `timeoutMs`:
a profile that sets or changes them changes its input key and reviews again.

## Compatibility

Four packages are aligned at 6.5.0 with the core peer floor `>=6.1.0 <7`
unchanged. Project does not import `@ccdd/core` and bundles its own budget
validation and enforcement, so it needs nothing new from core 6.5.0. Core 6.5.0
only adds the optional `maxToolCalls` and `maxTokens` fields to the TypeScript
`AgentProfile` type; use matching versions if you type manifests with it.
