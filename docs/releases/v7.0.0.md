# CCDD 7.0.0 — Project-independent identity cache

CCDD 7 reuses **explicit identity -> completed result** across projects,
repositories, paths, worktrees, Critic IDs and profiles. Only an owner identity
function makes a result reusable. Without one, every submission executes and no
result is reused or joined. This is a breaking change; follow the
[7.x migration](../migration-v7.md).

## Shared identity cache

- One local cache per user state home maps an identity value to a completed GREEN
  or RED result. Operational errors and cancellations are never cached.
- The same identity joins an in-flight computation from another repository or
  process without linking workspaces. Cancelling the initiating receipt does not
  cancel the computation while another subscriber remains.
- Ownership fencing, dead-owner recovery, bounded incremental GC, result integrity
  digests and oversized-result non-retention keep the store consistent across
  processes. A worker keeps serving shared executions after its own Run ends. An
  explicitly stopped owner drains briefly, then hands the identity to a remaining
  subscriber, which executes it again.
- `--force` executes once without reading, joining or replacing the shared result.
- `cache show/list/compare/gc/delete` work without a repository.

See [the cache contract](../identity-cache.md).

## Project and Broker

- Bounded identity preparation, read-before-write admission with atomic
  revalidation and bounded SQLite BUSY recovery preserve machine-wide capacity.
  A root `reviewPolicy.maxConcurrentExecutors` also caps shared executions.
- `--critics-file` and `--artifacts-file` select from bounded JSON or line files.
- `profileVariants` with `--profile` select declared execution profiles. Requested
  and actual profiles stay distinct on reuse; a retried subscriber uses its own
  requested profile.
- `prepareProject` / `submitPrepared` reuse one session's prepared submission.
- `streamProjectResults`, `run stream`, `run summary`, `request summary` and
  `run diff` provide cursor, result and attempt views.
- `graph --compact` supplies an indexed projection with grouped families and
  paged large-family expansion.
- Pi turns recover within one deadline under shared Provider/account cooldowns.
  `provider status/resume` expose recovery state. Models are never substituted
  and tool calls or partial responses are never replayed blindly.
- Human reviews joined from another repository are claimed, use tools and
  complete through the shared execution; the monitor lists that execution's tools.

## Breaking changes

- File hashes, `always` and an omitted `stale` no longer create a reusable key.
  Earlier GREEN Runs without an identity do not satisfy later status queries or
  dependency gates; verify with `--recursive` or declare identities.
- An identity value is global within the local user's cache. Audit constant
  values: the same value declares interchangeable results everywhere, including
  across Critics of one Artifact.
- Old composite keys remain history-only and are not imported.
- Stop old workers before switching runtimes. Use a private `CCDD_STATE_HOME` to
  isolate tests; `--state-dir` alone no longer isolates reusable results.

## Compatibility

Four packages are aligned at 7.0.0. Project and default-tools require core
`>=7.0.0 <8`. Node.js 22 LTS (22.19.0 or later) is required. Use matching
versions, or install `@ccdd/ccdd`.
