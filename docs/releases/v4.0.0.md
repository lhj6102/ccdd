# CCDD 4.0.0 — Artifact-owned verification

This major version makes each folder with `ccdd.json` responsible for its views and Critics. Configuration is static JSON; Project discovery never imports configuration modules or runs user scripts.

- Critic targets are implicit owners. Instruction references derive dependencies, with local mount aliases and qualified `artifact/critic` IDs.
- Nearest Artifact children and logical mounts add equal-level dependencies without copies, symlinks or merged child configuration.
- Views declare fixed script commands and accept the versioned JSON stdin/ToolResult stdout contract. Default tools are optional explicit registrations.
- Cycles are supported. Ready Critics execute together; final satisfaction requires matching actual evidence throughout the required scope. Partial results are preserved as INCOMPLETE.
- Strongly connected component hashing includes material, config, implementation inputs and relationships. Queries compute freshness from actual evidence, never stored stale flags.
- CLI, monitor, examples, demo and installed-package verification use the folder model. The monitor distinguishes execution progress from missing validation evidence and displays cyclic relationships.

Global config loaders/factories, artifact type registration, groups, generated sources, frozen JSON preparation and legacy execution routes are removed. Previous input versions remain readable as stored results but cannot be reused or resumed. Parameter-product Artifact generation is deferred. See [migration steps](../migration-v4.md).

Node support remains 22 LTS, at least 22.19.0. Core, Project and optional default-tools move together to version 4. Reviews continue to use the unchanged user-supplied workspace with external state/output; no copy/lock selector or remote workspace transfer is introduced.
