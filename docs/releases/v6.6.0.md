# CCDD 6.6.0 — Artifact families and Pi 1.0.0

## Artifact families

A `ccdd.json` with `family` declares many Artifacts that share one folder, its view
scripts and its Critics, through a static instance list:

```json
{
  "name": "skills",
  "family": {
    "instances": "instances.json",
    "params": { "instruction": "Evaluate the skill." },
    "variants": { "tripods": { "passSchema": { "type": "object", "properties": {}, "additionalProperties": false } } }
  },
  "critics": [{ "id": "evaluate", "title": "Evaluate", "profile": { "kind": "human" },
    "passSchema": { "$param": "/passSchema" }, "payload": { "instruction": { "$param": "/instruction" } } }]
}
```

```json
{ "SkillArtifact_305_34040": { "variant": "tripods", "material": ["states/305_34040.json"] } }
```

- Each listed name is an ordinary Artifact with its own Critics, evidence and relations.
  The family name is reserved; it cannot be mounted or referenced, and in a selection
  (`plan skills`, `verify skills`, `history skills`) it selects every instance.
- `{"$param": "/json/pointer"}` values in `views` and `critics` copy the instance's
  parameters: a shallow merge of `family.params`, the entry's `variant` and its own
  `params`. Nothing is evaluated; discovery still only reads JSON.
- `material` lists files that belong to one instance. They must exist inside the family
  folder. Shared scripts find them in `context.scope[artifactId].family.material`;
  identity and result-check scripts receive `artifactId` and `family` on stdin.
- Each instance's identity covers the shared material, its resolved definition, its
  merged entry and its own material. Editing or adding one instance, or a variant that
  others do not use, leaves sibling evidence current.
- A parent folder sees each instance as a logical child `<family folder>/<instance>`.
  The default `list` tool shows the folder as `kind: family`.
- The monitor shows a family as one node with an instance list, and can expand it.

See [the contract](../contracts.md#artifact-families), the
[example](../../examples/artifact-families/README.md) and the
[adoption note](../plans/artifact-families.md).

An owner-identity Artifact moved into a family keeps its ValidationInput key when its
name, Critic local ID, relations and returned value are unchanged. lostbuilds-rs moved
its 845-skill catalog into a family with all 845 reviews reused, byte-identical tool and
result-check outputs, and about 0.5 s discovery. A project that rewrites its workspace
still needs its own write coordination; see [#90](https://github.com/lhj6102/ccdd/issues/90).

## Pi 1.0.0

Project and the umbrella use `@earendil-works/pi-ai` and `pi-agent-core` 1.0.0. The
Pi executor and catalog are unchanged.

Pi 1.0.0 removed the harness read tool that `view_image` used to detect image formats.
default-tools now reads the bound file itself and detects PNG (not animated), JPEG
and WebP from exact content bytes, with the same 4 MiB bound, symlink and regular-file
checks and error messages. default-tools no longer depends on any Pi package.

## Identity

Existing review identities are unchanged; the golden identity tests pass without
modification. Ordinary Artifacts hash exactly as before. Identity scripts now receive a
small JSON object on stdin; scripts that ignore stdin are unaffected.

## Compatibility

Four packages are aligned at 6.6.0. Project keeps the core peer floor `>=6.1.0 <7`
because it bundles its own resolver. default-tools now requires core `>=6.6.0 <7`: its
`list` and `read` use core's `resolveScopePath`, which keeps family folders behind
their instances. State format stays 6. Use matching versions, or install `@ccdd/ccdd`.
