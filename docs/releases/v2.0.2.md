# CCDD v2.0.2

This release makes CCDD's documentation, CLI, monitor, examples, and built-in review instructions English. All three packages use version 2.0.2: `@ccdd/core`, `@ccdd/project`, and `@ccdd/default-tools`.

## Easier to get started

The README introduces the project as an Artifact DAG, with CCDD's Artifact and validation layers in the middle and Agent, Human, and Runtime reviewers on the right. Configuration and execution use different line styles and colors.

New guides show a first review using actual Node tests, custom Artifact tools, Agent configuration, and Human review submission. Existing contracts and historical verification records are available in English. The CLI and monitor use English labels and diagnostics, and built-in Agent instructions request English summaries and evidence.

Unicode project materials remain supported. Encoding tests preserve their original multibyte data through explicit Unicode escapes. Contribution guidance and a language regression check keep repository text consistent.

## Reliable read-only queries

- Project and repository-identity readers wait up to five seconds for transient SQLite locks while remaining read-only. This prevents an immediate `database is locked` failure when observing a resumed Human review during worker handoff.
- Unfiltered review-request lists sort by the stored creation timestamp and row insertion order. Per-Run lists retain their original ordinal order.

Regression tests cover transient and persistent locks, unchanged stored data, read-only enforcement, malformed and missing stores, and request ordering.

## Upgrade

```sh
npm install --ignore-scripts @ccdd/core@2.0.2 @ccdd/project@2.0.2 @ccdd/default-tools@2.0.2
npx ccdd-project config check
npx ccdd-project tools check
```

Install core and Project if your configuration uses only custom tools. The definition and tool interfaces remain compatible with v2.0.1. Existing review snapshots and recorded results retain their original content; new validation uses the installed executor version when deciding whether previous evidence can be reused.

Node.js 24 or later is required. The release command verifies the selected commit, runs the complete test suite, and checks actual production package installation and tool/Runtime execution before publishing. Publication is complete only when the npm registry confirms all three packages.
