# CCDD v3.3.0

CCDD 3.3.0 reduces review preparation and result-handling overhead and adds an
optional metadata integrity policy. Content integrity remains the default.
All three packages release together: `@ccdd/core`, `@ccdd/project`, and
`@ccdd/default-tools`.

## Changes

- Remove duplicate workspace validation, bound filesystem concurrency, and
  reuse the observer that validates a published copy. Idle lock waiting avoids
  full content scans, and Agent SDKs load only for Agent operations.
- Add `--integrity content|metadata` to Project `verify`, `status`, and `plan`.
  Metadata mode hashes the initial input, then checks complete metadata and
  structure at later boundaries. It assumes trustworthy filesystem metadata;
  its review evidence cannot satisfy a content-policy query.
- Reuse a verified staged copy at publication under metadata integrity when
  directory identity, structure, and metadata match. Unexpected differences
  fall back to byte validation. Content mode retains the full published-byte
  check, and cached copies receive one full validation under either policy.
- Preserve generated Artifact preparation, captured data, and policy-specific
  evidence identities. The additional copy optimization stays inside existing
  workspace acquisition without a new public API or persisted proof.
- Report mutations during read-only copy acquisition consistently as
  `WORKSPACE_CACHE_TAMPERED`.

## Performance evidence

On Linux with Node 22.22.0, the additional publication optimization reduced
fresh-copy metadata overhead from 43.20 s to 37.55 s, or 13.09%, across three
alternating measured pairs. Both implementations used metadata integrity,
16,000 one-KiB files, a 64-MiB binary, and a fresh CCDD copy cache per attempt.
The comparison starts from the original optimization integrated with v3.2.0.

This is not a default-policy speedup claim. The original Windows measurements
compared different integrity policies, and the full fresh-copy performance
target in issue #26 remains open. See the [benchmark method and raw
reports](../performance.md) for scope and limitations. Synthetic fixture
verdicts are not actual Human or Provider approval.

## Install and upgrade

```sh
npm install --ignore-scripts @ccdd/core@3.3.0 @ccdd/project@3.3.0 @ccdd/default-tools@3.3.0
```

Node.js 22 LTS (22.19.0 or later) is required. Default tools remain optional
when all tools are custom. Existing configurations and stored reviews remain
compatible without migration; active reviews retain their original snapshots
and policies. Metadata integrity is an explicit choice for subsequent queries
and reviews. See the [integrity contract](../contracts.md#optional-metadata-integrity).

## Verification

Independent Standards and Spec reviews passed, including the constraint to
keep additional optimization within the existing domain model. The integrated
runtime passed all 426 tests and both production-package installation checks
