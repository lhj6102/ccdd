# v0.3.0 verification

Validated on macOS with Node 24.15.0. Filesystem watcher tests require native filesystem access; the restricted execution sandbox reports fs.watch EMFILE and CCDD correctly refuses unmonitored reviews there.

## Automated checks

**76 tests passed, 0 failed.** This includes real subprocesses and filesystem changes, not only adapter fixtures.

- Whole-workspace content hashing includes untracked and ignored input; no Git repository is required.
- Concurrent processes publish/reuse one read-only copy and retain independent results/output directories.
- Capture-time changes leave no published partial copy; later original changes do not affect copied input.
- Lock detects additions, deletion, edit-and-restore and submit/worker handoff changes.
- Cache tampering invalidates active users and prevents future reuse.
- Separate CLI processes run, query and complete reviews with no listening server.
- Wait timeout preserves running work. Duplicate resume never duplicates execution. Closing another client leaves ownership intact.
- Human-copy waiting survives worker exit and original source deletion. Separate commands read copied Artifacts, claim and complete once.
- Immediate Human completion races are covered at both validation and ownership release boundaries.
- Human-lock waiting keeps monitoring; changes or worker loss prevent acceptance.
- Startup IPC disconnection does not kill an owned review worker.
- Explicit cancellation, dead-owner reconciliation, failed alarms, scoped tools, actual Node test exits and Provider diagnostic failures are exercised.
