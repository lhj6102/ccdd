# v0.6.0 verification

Validated on macOS with Node 24.15.0. Pi Agent Core and Pi AI remain pinned to 0.85.1.

## Minimal local monitor

`ccdd monitor` serves an optional web UI on 127.0.0.1. Its first screen shows request titles, projects, statuses, and elapsed time. Project and active/attention filters narrow the list. Selecting a request reveals its result, expandable evidence and instruction, lifecycle times, and scoped Artifact browsing. Human actions and Provider editing remain CLI workflows.

No new review telemetry, state schema, or provider calls were added. Elapsed time starts with the existing acceptance record after workspace preparation. Requests blocked by a failed predecessor show that they cannot proceed; they do not accumulate a misleading active-duration display.

## Automated validation

Strict TypeScript checking passed. **134 tests passed, 0 failed**, including 20 new monitor tests.

- Read-only queries preserve broker records even when a stored worker is dead. Missing/corrupt projects are isolated; copied history remains discoverable after source deletion.
- Canonical project identity, default/explicit discovery, cross-project filters, counts and pagination are covered. The 2,001-request fixture exercises larger histories without per-row map reconstruction.
- Human copy waits without an owner are normal; claim can precede notification delivery. Timeline reads are not truncated at 500 events. Failed predecessors remain distinct from active dependency waits.
- Detail and overview responses project only permitted fields. Ownership tokens, credential files and raw provider logs are not exposed.
- HTTP requests enforce loopback Host/origin, GET-only access, valid identifiers/arguments, and bounded concurrent Artifact reads. Scope traversal and altered stored descriptors/Artifact definitions are rejected.
- Artifact reads use existing Viewer tools and validate snapshot integrity before and after access. Missing or modified input fails explicitly. Disconnect/time-limit cancellation stops the read and closes its workspace handle.

## Browser validation

The real browser loaded historical Astra results through the installed package: a GREEN chain and a RED Why/Spec mismatch. Project selection, attention filtering and its empty state, result details, directory-to-file navigation, and jumping to line 10 of Spec worked.

The UI was inspected at desktop 1280×850 and mobile 390×844. The mobile document width matched its viewport with no page overflow; long code lines scroll inside the reader. No browser error/warning logs were recorded during the final installed-page check. Live refresh preserves an open Artifact reader and its input; request selection resets detail scroll and stale detail responses are discarded.

## Independent installation

A production-only candidate package was installed in a separate temporary prefix. The actual `ccdd` executable served HTML, CSS, client JavaScript, overview/detail data and a CRLF Artifact partial read. Out-of-scope Artifact access and mutation requests were rejected. No Codex CLI or TypeScript compiler was installed.

Runtime diagnosis/review and Human waiting/claim/result/resume passed. Saved worker settings contained authentication paths without credential contents.

An actual slow runtime request appeared as RUNNING with an alive worker. After the installed monitor exited cleanly on SIGTERM, the same Run remained RUNNING and later reached GREEN. This verifies that the monitor does not own or cancel execution.

All 72 packaged JavaScript, declaration and source-map files were checksummed. The final release package must match the tested candidate code; adding this verification document changes no executable files. Sanitized installation and browser verification records accompany the release.
