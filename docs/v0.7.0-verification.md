# v0.7.0 검증 기록

검증일: 2026-09-06 (Asia/Seoul). Node.js 24.15.0에서 서버 TypeScript 검사와 Vue 컴포넌트 검사를 수행했습니다.

## 자동 검증

`npm test`: **164개 통과, 실패·건너뜀 없음**. 서버는 TypeScript 7.0.2, Vue SFC는 vue-tsc가 지원하는 별도 TypeScript 6.0.3으로 검사합니다. 빌드는 각 컴파일러의 명시적 경로를 사용해 npm 실행 파일 별칭 충돌을 피합니다.

- 명시적 Agent/Human 도구 목록, 비어 있는 대상 목록의 요청 거부, 개별 Critic 선택, 기존 스냅샷 열람 호환.
- 등록된 고정 인자 실행, Artifact 경로 제한, 실행 중 입력 변경, 취소·시간 제한·하위 프로세스 정리, 출력과 Provider 환경변수의 노출 방지.
- 도구 사전 검사와 실제 실행, 짧은 도구명과 공개된 전체 이름, 검사 중 리뷰 기록 미생성.
- 브라우저 담당자·CSRF 검사, 중복 작업·판정 방지, 스냅샷과 요청 범위 일치, 129자 도구 이름 처리.
- 서버 재시작 후 담당자 유지, 원본이 사라진 복사본 리뷰, 서버 종료 후 독립된 후속 Runtime 작업 완료.
- 기존 workspace lock/copy, Agent의 필수 관측·구조화된 판정, Human 영속 대기, 실제 Node 테스트 실행 회귀.

## 브라우저 확인

기존 실제 Astra 리뷰 기록과 별도 UI 검증용 프로젝트를 함께 연결했습니다. UI 검증용 판정에는 테스트 기록임을 명시했으며, 실제 프로젝트의 Human 품질 판정을 대신하지 않았습니다.

- 1280×850에서 프로젝트 선택과 네 칸반 영역을 확인했습니다.
- Human claim 후 요청 카드가 진행 중으로 이동했습니다.
- 도구 버튼 한 번으로 파일을 읽고, 다음 줄 읽기로 81번째 줄부터 이어 읽었습니다.
- `open` 도구로 리뷰 복사본의 `spec.md`가 CotEditor에서 실제로 열린 것을 확인했습니다. 원본 workspace와 다른 복사본 경로였습니다.
- 주기적 화면 갱신과 프로그램 열기 중 판정 초안이 유지됐습니다.
- UI에서 GREEN과 요약·근거를 제출한 후 실제 후속 Node 테스트도 GREEN으로 완료됐습니다.
- 기존 Agent 리뷰의 Spec과 Tests 디렉터리·파일을 계속 읽을 수 있었습니다.
- 390×844에서 상세 화면과 보드를 확인했고, 문서 폭은 390px로 가로 넘침이 없었습니다. 콘솔 오류·경고가 없었습니다.

## 설치 경계

생성한 npm 아카이브를 별도 경로에 운영 의존성만 설치하고 설치 스크립트를 비활성화한 상태에서 CLI·모니터 자산·도구 검사를 확인합니다. Vue 화면은 외부 CDN 없이 패키지의 JS/CSS를 사용하며, 실행 환경에 Vite·TypeScript·vue-tsc가 필요하지 않습니다. 아카이브 체크섬과 설치 검증 결과는 릴리스 검증 자료에 별도로 보관합니다.

## 적용 범위

이번 변경에서 새 Provider 실사용 호출은 하지 않았습니다. Agent 실행 계약의 회귀와 기존 실제 Astra 기록의 호환을 확인했습니다. Human 프로그램 사전 검사는 실행 파일의 존재·실행 가능성과 Artifact 경로까지이며, 앱별 실행 성공은 `tools check --execute` 또는 명시적 도구 버튼 실행으로 확인합니다. 프로그램이 열렸다는 결과는 사람의 열람이나 판정을 자동으로 의미하지 않습니다.

새 Agent/Human 요청에는 대상별 도구 목록이 필요합니다. 기존 데모를 다시 쓰지 않도록 새 기본 데모는 `demo-v7`에 생성됩니다.
