# v0.5.0 verification

Validated on macOS, Node 24.15.0, TypeScript 7.0.2, and Pi Agent Core / Pi AI 0.85.0.

## Build and automated checks

All application, demo-generator, and test sources are TypeScript. The strict NodeNext typecheck and clean build pass. **113 tests passed, 0 failed.** The npm package runs compiled JavaScript and does not need TypeScript installed at runtime.

- Broker, workspace ownership, copy sharing, lock mutation detection, cancellation and Human completion/restart regressions remain covered.
- Request/result/profile types live in a common contract without Pi imports. Pi library imports are confined to the Agent executor implementation.
- Pi's real Agent loop is exercised with scripted transports for OpenAI Codex and Anthropic. Only transport responses are fixtures; Artifact reads, argument checks, observation records and final schema validation are real.
- Direct Pi tools and stdio MCP share one successful-call audit wrapper. Original arguments are checked before Pi can coerce values; failed, aborted, listing-only and past-EOF reads cannot fabricate required inspection.
- Unknown Providers/models and substituted reasoning levels are rejected. Server model fallback permission is removed from the per-request model. Assistant Provider/model identities are checked before executing their tools.
- Native Anthropic request payloads were inspected without network calls to verify low/medium effort on managed-effort models and absence of fallback model parameters.
- Both provider/network errors and thrown transport failures are sanitized. Invalid or incomplete final JSON is an execution error, not a RED verdict.
- Sparse multi-gigabyte Artifact reads honor cancellation during scanning. No successful observation is recorded for an aborted read.
- Credentials inside the source workspace are rejected before copying through both CLI and programmatic Broker/Doctor entry points. Explicit file adapters are read-only and do not refresh shared tokens.

Filesystem watcher tests use native access. The restricted macOS execution sandbox reports fs.watch EMFILE; CCDD refuses unmonitored reviews in that environment.

## Migration limits

Use Pi Provider IDs and catalog-supported models explicitly. Pi 0.85.0 does not list `gpt-6-astra`; CCDD does not replace it. The fresh demo-v5 uses `gpt-5.6-sol`. The old `--codex` binary option is removed.

Provider API key environment variables or explicit `--pi-auth-file` / `--codex-auth-file` paths configure authentication. Current file connections are read-only: OAuth tokens expiring within five minutes are rejected and must be renewed by their issuing login tool. Authentication is not automatically inherited from Codex CLI.

Pi packages are reused as pinned dependencies from the [official project](https://github.com/earendil-works/pi), not copied into CCDD sources.
