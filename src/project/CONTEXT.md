# Project Validation

Project Validation discovers static folder/family declarations and typed child,
mount and instruction relations. It prepares a selected finite dependency scope,
invokes explicit owner identity functions, and requests missing results through
the Broker. Discovery itself is inert.

The owner function alone defines reusable result equality. Equal values reuse
across repo/path/Critic/profile; no function means no reusable key. SCC/content
fingerprints remain graph/integrity metadata and never partition the cache.
A completed noncached result satisfies its own Run, not later submissions.

Individual validation executes selected Critics; recursive validation includes
the required dependency closure. External dependency GREEN gates are the default;
SCC peers have no internal gate. `ignoreGates` explicitly bypasses execution gates.
Final satisfaction requires actual GREEN throughout the required scope. Missing
required evidence is INCOMPLETE, RED remains unsatisfied, and operational failure
is never a fabricated verdict. No-Critic Artifacts are UNREVIEWED unless basis.

Prepared handles are session-only, detached from mutable public views and checked
against the unchanged workspace on submission. Profile variants are execution
settings, not cache salts. Public read-only result/cursor/summary/comparison APIs
keep consumers independent of SQLite internals. History from previous input
versions is readable where supported but never reused or resumed.
